How to read the tables in section 2

- **Decisive assertions** quotes the status codes, exact strings, counts and comparisons that make the test fail. Exact strings
  are in backticks and copied from the test.
- **EF/SQLite-bound** is `no` when the assertion is about the wire contract or a domain rule and ports unchanged. Otherwise it

### 1.4 `DatabaseProbe` (`AuthFactory.cs:43`): what the suite counts

An EF Core command and transaction interceptor registered on the factory's `AuthDb`.

- `Commands` counts every reader, scalar and non-query command before it runs (`:90`); `Sql` keeps each command text in a queue; `Rows` adds the reader's `ReadCount` when a data reader is disposed (`:116`); `Transactions` counts started transactions (`:119`); `Reset()` zeroes all counters and the queue (`:53`). A test brackets one HTTP call with `Reset()` and then asserts the counters.
- `Interleave(table, sql, times = 1)` (`:61`): just before each of the next `times` commands whose text contains `UPDATE "<table>"`, runs `sql` on the same connection and transaction (another writer's change landing between the API's read and its write). Used in `ChangeLogAndScopeTests.cs:126`, `:136`, `:168`, `:180`, `:197`, `:215`, `RevenueCaptureTests.cs:260`, and `PettyCashTests.cs:488-489` (grep only, not read).
- `BetweenAttempts(sql)` (`:72`): runs `sql` on the connection (committed on its own) just before the second transaction opened after arming (a change landing after a unit of work's first attempt rolled back and before it retries). Used in `AuthTests.cs:550` and `ChangeLogAndScopeTests.cs:169`, `:198`.
- `FailNextCommit` (`:52`, `:123`): the next `TransactionCommitting` throws `InvalidOperationException("Simulated commit failure.")` once. Used in `AuthTests.cs:534`, `:548`, `:566`, `OperabilityTests.cs:117`.
- `AuthFactory.ExecutionStrategy` (`:163`) **(uncommitted)** lets a test install `RetryOnSimulatedFailure` (`:131`) **(uncommitted)**: an EF `ExecutionStrategy` with 3 retries and a 1 ms delay that retries only that exact message. SQLite has no retrying strategy of its own, so without it the API's retry loops cannot run; tests set it before the first request (`AuthTests.cs:547`, `:565`).
- Tests that bypass the probe and count on their own connection: `RevenueComplexityTests` (a private `Counter` that counts executed readers and scalars and sums `ReadCount`, `RevenueComplexityTests.cs:184`) and `ExpenseCatalogTests` (`CommandCounter` counting `ReaderExecutingAsync` only, `ExpenseCatalogTests.cs:186`, on a private SQLite connection and a hand-built `SetupRepository`).
- Counting conventions differ: `VehicleReportTests.cs:209` and `RecurringQueryCostTests.cs:30` count only statements starting with `SELECT`; `ChangeLogPagingTests.cs:106` searches the text for `COUNT(`; the others use `Commands`. Section 5 turns all of these into statement budgets.

### 1.5 Fakes and captured output

- `TestClock : IClock` (`:22`): `UtcNow` starts at the real `DateTimeOffset.UtcNow`; `Advance(span)` moves it (negative spans too, which tests use to move "the business date back", for example `AccessAndSetupTests.cs:154`, `ExpenseCatalogTests.cs:98`, `AutomaticReasonTests.cs:86`, `OrganizationSettingsTests.cs:163`). Clock-dependent tests do not freeze time: `TheChangeLogIsNarrowedByItsFilters` uses the real `DateTime.UtcNow` for its `from` and `to` filters (`ChangeLogAndScopeTests.cs:273`), which can disagree with the factory clock around midnight UTC.
- `TestEmail : IEmailSender` (`:27`): `Codes` (latest code by address), `Count` of deliveries, and a `BeforeSend` hook that can block or throw for an address (`AuthTests.cs:177`, `:601`, `:636`). Auth tests wait on `VerificationMailer.Idle()` after each request because codes go out after the response (`AuthTests.cs:26`).
- `TestLogs : ILoggerProvider` (`:138`): keeps log entries at level Error and above as `(category, structured values)`; tests read `UserId` and `CorrelationId` from the entry (`AuthTests.cs:643-645`, `:663-664`).
- `Seen(path, request)` (`AuthTests.cs:38`): "everything a caller can see of a response, to compare two byte for byte": status code, all response and content headers except `Date`, `Content-Length` and `X-Request-ID`, ordered by name, then the body text. Used to prove that a paused account on an untrusted device, an unknown number and a non-phone input are indistinguishable (`AuthTests.cs:64`, `:160`, `:166`). Any new per-request header the Python app adds must be excluded here, as `CLAUDE.md` says.

### 1.7 Waits and concurrency used by tests

- Real waits: 20 s for a request to finish while the mailer is blocked (`AuthTests.cs:181`, `:616`), polling up to 200 x 50 ms for the mail (`:186`), 2 s to show a request is still blocked (`AuthTests.cs:586`), 30 s for a send to start (`:611`), 10 s for 16 concurrent cache callers (`RevenueDashboardCacheTests.cs:208`). `CLAUDE.md` notes these time out under machine load.
- Real parallelism: five concurrent wrong-PIN requests (`AuthTests.cs:437`), two sign-ins on different numbers (`AuthTests.cs:722`), 16 concurrent cache callers (`RevenueDashboardCacheTests.cs:198`). SQLite in-memory on a single shared connection serializes the writes, so these tests prove the application-level locking and the optimistic tokens, not database isolation.

### 4.2 Auth numbers and behaviours that no design states

- Defaults: 5 wrong PINs pause for 15 minutes (`AuthTests.cs:35`, `:87-88`, `:239-251`); the timer is shown from the wrong PIN that starts the pause (`AuthTests.cs:78`); the pause ends exactly at the tick (`AuthTests.cs:246-249`).

### 6.2 Open questions

1. **Which strings are contract.** Section 4.3 lists every exact message a test pins. The Python rewrite must either reproduce them or the clients and tests must change together. The 403 and 409 problem `title` and `detail` strings are shown to people by web and mobile (`apps/web/tests/request.test.ts:10-20`), so they are contract; the startup messages (`Email:Host is required.`) are .NET configuration key names and are probably not.
2. **Exact command counts.** `PeopleQueryCostTests.cs:195` pins 10 and 5 commands. They describe EF's behaviour (token check, membership, settings reads). Should the Python port freeze its own measured numbers, or only a ceiling?
3. **Revenue 409 title.** The race test pins `This day was changed by another save.` (`RevenueCaptureTests.cs:266`); the version-mismatch test (`:131-133`) only requires a non-blank title and detail; the mobile fakes use `This day already has a different record.` (`apps/mobile/tests/revenue.test.tsx:262`). One string should be chosen; clients branch only on 409 and `current`.
4. **Audit and version tables as contract.** Tests read `AuditEvents` actions `organization.settings.updated` and `person.sign_in_details_changed` and the `OrganizationSettingsVersion` snapshots with `"Role":"Fleet manager"` and `"lockoutThreshold":3` JSON (`AccessAndSetupTests.cs:434`, `AccessLifecycleTests.cs:234`, `ChangeLogAndScopeTests.cs:60-62`, `:235-236`). Do the snapshot JSON property names (PascalCase for people, camelCase for settings) survive into Python, or does the change-log API expose a different shape?
5. **Dashboard cache scope.** `RevenueDashboardCache` is in process, keyed by organization, settings version, business date, period, company and scope, and masked per request after the cache. A multi-worker Python deployment either shares the cache, accepts per-worker caches, or drops it. The tests assume one process.
6. **Brotli.** `CompressionTests` requires `br` and `gzip` and prefers `br`. A comment in the uncommitted `apps/api/Program.cs` diff says Brotli is for browsers and gzip stays because React Native's fetch sends only gzip, and that auth bodies are never compressed because of BREACH; the Python stack must support gzip, Brotli is optional but then `CompressionTests.cs:53` rows 1 and 3 change.
7. **Clock.** `TestClock` starts at the real time; `ChangeLogAndScopeTests.cs:273` reads `DateTime.UtcNow` directly, and `PinnedThursday` depends on the clock date. A frozen clock fixture is needed for the Python suite; decide the fixed date.
8. **Runtime-mutable settings.** `AuthTests.cs:398` sets `AuthOptions.TrustLifetimeDays` on the live singleton; `ForwardedClientTests` and `ProductionStartupTests` change configuration per host. Python settings need an override mechanism per test app.
9. **Rate-limit defaults.** `ForwardedClientTests` sets `RateLimiting:AuthPermitLimit` to 2; the production default and window are not asserted by any test.
10. **Duplicate test.** `SetupMigrationSnapshotTests.TheMigrationSnapshotMatchesTheModel` duplicates `MigrationSnapshotTests.TheSnapshotMatchesTheModel`; port once.
