## 2. Deviations from the documents, with reasons, and the lines changed

- `setup.split_week` is not a routine. Migrations run before routines exist, so nothing could
  call it from `0010`; the split is inline in `0010_setup.sql` with a comment on why `round`
  equals half-even for a seventh. `docs/05` 10.4 (the helper row) and `docs/10` 3.1 now say
  so.
- `setup.vehicle_target_sets.created_by` is nullable: the sets `0010` makes from the weekly
  targets have no author (none was stored). Every routine write sets it. `docs/04` 13.4.
- `setup.target_on` stays as a bridge (week total of the set in force) instead of being
  replaced by `setup.day_target` in D3: the revenue routines are D4's. `docs/05` 10.4.
- An earlier join date copies the vehicle's first set to it (the documents said "the earliest
  set"; my first build copied the set in force on the old join date, which differs only when
  migrated sets precede the old join date and then leaves a timeline that is not monotonic).
- The list's `day_targets` shows the set in force also while the vehicle is away or after it
  left (null only when no set has started); `weeklyTarget` keeps its released meaning (0 while
  away). `docs/06` S17, `docs/05` 10.4.
- The list's `targets` (released shape) holds only sets that have started: the released web
  labels every entry but the newest "Was from …", which would mislabel the set in force once a
  future set is listed. The future set is in `nextTarget`. `docs/06` S17.
- A category rename and move together read "Renamed expense category X to Y, moved to main
  category Z" (as the .NET rename-and-bucket sentence), not two full sentences. `docs/05` 10.4.
- The save raises `target_start_required` before the figures check (an absent start date); the
  vehicle row is locked before the visibility check. `docs/05` 10.4.
- Deliberate changes for released clients (`DEC-15`, DN-B10-1, DN-B17-3): a vehicle save
  without a fleet number answers 400 "Enter the fleet number." (`tests/api/
  test_contract_released_clients.py::test_a_vehicle_save_from_the_develop_web_is_refused_until_it_sends_a_fleet_number`);
  `weeklyTarget` and `bucket` in bodies are ignored; scheduled-item change-log reasons read
  "Scheduled expense, [name]" / "Saving, [name]".
- Outside D3's own files, claimed on the board first: `tests/support/rows.py`
  (`seed_organization` rows), `tests/support/tenancy.py` (`add_vehicle` `fleet_number`),
  `tests/db/test_access_routines.py` (two vehicle-option dicts), `tests/unit/test_messages.py`
  (one sample), `tests/db/test_tenancy_isolation.py` (count 29; the insert test limited to
  insertable tables, since `setup.vehicle_targets` lost its INSERT grant),
  `tests/db/test_grants.py` (append-only list), `tests/db/test_migrate.py` (one test),
  `tests/api/test_openapi.py` (six rows), `db/routines/30_tenancy/access_{scope_options,
  my_scope}.sql` (the `fleet_number` key, released by D2), `docs/10-data-migration.md` 3.1
  (one phrase).
