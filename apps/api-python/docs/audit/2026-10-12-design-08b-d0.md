### 8.3 Conceded challenges (the guard that holds)

- The ledger search (CE-20: ILIKE over registration, item, category, note, names) has no
  index: the period index `(organization_id, entry_date)` and the 367-day cap bound the rows
  scanned; the search filters that set. `docs/04` 14.2 says "an index per query"; the search
  is a filter, not a query.
- `decide_saving_runs` is called from `api.setup_vehicle_update` after the vehicle's
  `FOR UPDATE`: the advisory lock always follows the vehicle row (`docs/05` 11.1's rule), and
  no routine takes the advisory lock first, so no opposite-order pair exists.
- A 30-day window run dated `saved day + 29` is decided by that save: `least(p_last + 29,
  today)` reaches it; a later day cannot complete an earlier window that is still incomplete,
  because its missing day is older than the saved one.
- A run dated on the opening date: `DEC-35` counts saved runs "dated after the opening date",
  so the opening amount absorbs it; the test named in the plan asserts it.
- Two day saves with opposite row orders: both lock rows in ascending vehicle id (`DEC-42`),
  and new records' unique entries are taken in that order.
- A racing retried purchase: the purchase id's advisory lock precedes the lookup, so the loser
  waits and then finds the winner's rows (CE-8's answer); the unique `(organization_id,
  group_id, vehicle_id)` is the backstop.
- Formula injection through a note: `write_string` with the three `strings_to_*` options off
  and the quote prefix; the note itself is unchanged, so the ledger and the file agree.
- The web names files itself (`exportReport.ts`); the `Content-Disposition` name is for other
  callers, so a non-ASCII organization name cannot break the web.
